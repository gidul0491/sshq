# sshq: SSH 조회와 백업 후 수정

서버 확인이 필요하면 사용자에게 접속해서 봐 달라고 하지 말고 직접 실행한다.

```bash
sshq                                     # 별칭 목록 (현재 프로젝트를 쓰는 별칭에 *)
sshq <별칭> "<명령>"                      # 조회 명령 실행 (root 폴더에서)
sshq get <별칭> <원격경로>                # work/<별칭>/ 아래로 내려받기 (폴더도 가능)
sshq diff <별칭> <원격경로> [로컬경로]     # 원격과 로컬 사본 비교 (폴더면 바뀐 파일·새 파일 목록)
sshq put <별칭> <원격경로> [로컬경로]      # 원격을 ~/_sshq_backup/에 백업한 뒤 업로드 (폴더면 바뀐 파일만 묶음으로)
sshq restore <별칭> <원격경로> [백업]      # 백업으로 되돌리기 (생략 시 가장 최근 백업)
sshq restore <별칭> --batch [묶음]         # 폴더 put 묶음 전체 되돌리기 (생략 시 묶음 목록)
sshq log <별칭> [줄수]                    # 서버를 바꾼 작업 기록 (put·restore·del·exec)
sshq del <별칭> <원격경로>                # 지우지 않고 ~/_sshq_to_delete/ 아래로 옮기기
sshq clean <별칭> [원격경로]              # work/<별칭>/의 로컬 사본 지우기 (생략 시 전부)
sshq backup <별칭> [원격폴더]             # backup/<별칭>/에 tar.gz로 받기 (생략 시 홈 전체)
sshq exec <별칭> "<명령>"                 # 제한 없는 명령
sshq set <별칭> projects +<프로젝트>      # 이 별칭을 쓰는 프로젝트 추가 (-<프로젝트>는 제거)
sshq set <별칭> <root|desc> <값>          # 수정, 빈 값("")이면 비우기
sshq set <별칭> mode readonly             # 읽기 전용 서버로 (put·restore·del·exec 거부, ""면 해제)
sshq new <별칭> [root] [설명]             # 새 서버 양식 추가 (접속정보는 빈칸)
sshq version                             # 설치된 버전과 새 버전 확인
sshq update                              # 새 버전으로 업데이트
```

## 버전 확인
- 세션에서 sshq를 처음 쓸 때 `sshq version`을 먼저 실행한다.
- 새 버전이 있으면 사용자에게 바뀐 내용(출력의 커밋 목록)을 한 줄로 알리고 `sshq update`로 업데이트한 뒤 작업을 계속한다.
- update가 로컬 수정이나 올리지 않은 커밋 때문에 멈추면 그 내용을 사용자에게 알리고, 직접 정리하지 않는다.

## 별칭 고르기
- 작업 중인 프로젝트 폴더에서 `sshq`를 실행해 `*` 붙은 별칭을 쓴다. 프로젝트 이름은 첫 줄 `현재 프로젝트:`에 나온다(git `origin` 저장소 이름 → git 최상위 폴더 이름 → 현재 폴더 이름 순).
- `*`가 없거나 여러 개면 추측하지 말고 사용자에게 묻는다. 사용자가 도메인이나 계정 ID로 말하면 목록의 `설명`·`root`와 맞춰 보고, 애매하면 묻는다.

## 조회
- 상대경로는 별칭의 `root` 기준, `~/`는 홈 기준, `/`로 시작하면 절대경로다. 조회 명령도 `root` 폴더에서 실행된다.
- 처음 보는 서버는 `sshq <별칭> "pwd"`, `sshq <별칭> "ls -la"`로 구조부터 본다.
- 큰 파일은 `cat` 대신 `head`, `tail -n 200`, `grep -n`으로 필요한 부분만 본다. 출력은 2000줄에서 잘린다.
- 코드를 몇 개 볼 때는 서버에서 `cat`·`grep`으로 본다. 폴더 `get`은 많은 파일을 로컬 도구로 한꺼번에 검사할 때만 쓰고, 받기 전에 `du -sh <폴더>`로 크기를 보고 크면 하위 폴더 단위로 받는다.
- 허용: 조회 명령(`ls cat head tail grep find stat wc du df ps php -v/-l/-m/-i tar -t git status/log/diff` 등)을 `|`로 이은 것. 따옴표 밖의 `;` `&&` `||` `>` `<`와 `` ` `` `$(`는 거부되니 명령을 나눠서 여러 번 실행한다.
- 거부되면 `exec`로 우회하지 말고, 조회로 나눌 수 있는지 먼저 본다.

## 수정 절차
1. `sshq get <별칭> <파일>` → 출력된 로컬 경로(`work/<별칭>/...`)의 사본을 Edit 도구로 고친다. 서버에서 `sed -i` 등으로 직접 고치지 않는다.
2. `sshq diff <별칭> <파일>`로 바뀐 내용을 확인하고, 사용자에게 diff 요점을 보여준다.
3. `sshq put <별칭> <파일>`로 올린다. put이 원격 파일을 서버 홈의 `~/_sshq_backup/<원래 경로>.bak_<시각>`으로 백업하고 확인한 뒤 업로드한다. 백업 경로는 출력에 나온다. 백업을 웹 폴더 안에 따로 만들지 않는다.
4. 올린 뒤 검증한다: PHP는 `sshq <별칭> "php -l <파일>"`, 웹 페이지는 로컬에서 `curl -sI <URL>`로 응답 코드를 본다.
5. 문제가 생기면 바로 `sshq restore <별칭> <파일>`로 되돌리고 사용자에게 알린다.
6. 검증까지 끝나면 `sshq clean <별칭> <파일>`로 로컬 사본을 지운다. 되돌리기는 서버의 백업으로 하므로 로컬 사본은 남기지 않는다. 폴더째 받아 검사만 한 사본도 검사가 끝나면 지운다.
- 여러 파일을 고칠 때는 핵심 파일 하나를 먼저 올려 확인한 뒤 나머지를 폴더 단위로 올린다: `sshq diff <별칭> <폴더>`로 바뀐 파일 목록을 사용자에게 보여주고, `sshq put <별칭> <폴더>`로 바뀐 파일과 새 파일만 한 묶음으로 올린다. 출력의 묶음 번호를 사용자에게 알린다. 폴더 put은 서버에만 있는 파일을 지우지 않는다.
- 묶음에 문제가 있으면 `sshq restore <별칭> --batch <묶음>`으로 한 번에 되돌린다. 바꾼 파일은 그 묶음 직전 상태로 돌아가고, 묶음에서 새로 만든 파일은 `~/_sshq_to_delete/`로 옮겨진다.
- `읽기 전용 서버입니다`가 나오면 우회하지 말고 사용자에게 알린다. mode는 사용자가 요청할 때만 바꾼다.
- 폴더 단위로 크게 바꾸기 전이나 서버 작업(PHP 버전업 등) 전에는 `sshq backup <별칭> [폴더]`로 로컬에 받아 둔다. 출력의 파일 수가 서버와 다르면 경고 내용을 사용자에게 알린다. DB는 포함되지 않는다.
- `backup/`의 백업 파일은 clean 대상이 아니며, 사용자가 요청하지 않으면 지우지 않는다.

## exec를 쓰는 경우
- 조회 명령으로 안 되는 것만 쓴다: 압축 백업, 디렉터리 생성, 권한 확인용 복합 명령 등.
- 삭제(`rm`, `rmdir`), 원본을 덮어쓰는 `mv`, 서비스 재시작, 패키지 설치, `chmod -R`/`chown -R`, crontab 수정, DB 쓰기는 사용자가 명시적으로 요청한 경우에만 한다. 삭제가 필요하면 `rm`·`mv` 대신 `sshq del <별칭> <경로>`로 옮긴다. 원래 경로 그대로 `~/_sshq_to_delete/` 아래로 가고(예: `www/a.php` → `~/_sshq_to_delete/www/a.php`), 폴더 권한은 700으로 맞춰진다. `~/`로 시작하는 경로는 로컬 셸이 바꾸지 않도록 `'~/...'`처럼 따옴표로 감싼다.
- exec 명령은 Claude Code가 실행 전에 사용자 승인을 받는다. 무엇을 왜 하는지 한 줄로 먼저 말한다.

## 설정을 직접 고치는 경우
- 사용자가 "여기는 ○○ 서버 쓰는 거야"라고 하면 `sshq` 첫 줄의 현재 프로젝트 이름으로 `sshq set <별칭> projects +<프로젝트>`를 실행한다. projects 전체를 덮어쓰는 `,` 형식은 쓰지 않는다.
- 사용자가 서버 용도를 설명하면 `desc`를 채운다. 근거 없이 추측으로 채우지 않는다.
- 사용자가 새 서버를 추가하라고 하면 `sshq new`로 양식만 만들고, 사용자에게 `sshq.json`에서 해당 별칭의 host·user·password 또는 key를 채워 달라고 한다. 별칭 이름은 기존 별칭처럼 짓되, 애매하면 묻는다.
- host·port·user·password·key·hostkey는 사용자만 수정한다. 이 값을 대화로 받아도 직접 넣지 말고 사용자가 파일에 넣게 한다.

## 하지 않는 것
- 접속정보 파일 `sshq.json`을 직접 읽거나 편집하지 않는다. `~/.ssh`의 키 파일도 읽지 않는다.
- 서버의 설정 파일에서 읽은 비밀번호·키·토큰을 대화에 그대로 옮기지 않는다.
- `sshq ...`는 단독 명령으로 실행한다. 파이프·`&&`·`;`로 로컬 명령과 묶으면 허용 규칙에 걸리지 않아 막힌다.
- 접속 오류(Authentication failed, Timed out, 서버 지문 불일치, 접속정보 미입력 등)는 추측으로 고치지 말고 그대로 사용자에게 알린다. 서버 지문 불일치는 사용자가 확인하기 전까지 다시 시도하지 않는다.

## 파일 위치
sshq 저장소 폴더(보통 `~/git/sshq`) 하나에 전부 있다. `~/.local/bin/sshq`는 이 폴더의 스크립트를 실행하는 런처, `~/.claude/skills/sshq`는 `skill` 폴더 링크다.
- `sshq`: 스크립트
- `sshq.json`: 접속정보 (git 제외, 각자 입력)
- `work/`: `get`으로 내려받은 사본 (git 제외)
- `backup/`: `backup`으로 받은 tar.gz (git 제외)
- `skill/SKILL.md`: 이 스킬
